# Agent 대화·버튼·화면 이동 추가 점검

## 범위

폴더 평가, 규칙 적용·해제, 결과·분석·내보내기 개선분에 이어 Agent 대화 저장, 목록 복원, 비동기 버튼 동작과 폴더 이동을 다시 점검했다. 기능을 줄이지 않고 현재 실행과 화면 선택이 어긋나는 경로를 수정했다.

## 확인하고 수정한 문제

| 조건 | 기존 문제 | 수정 |
| --- | --- | --- |
| 프로젝트 대화 100개 / 한 대화 500개 메시지·300개 도구 기록 초과 | 저장 시 과거 데이터 자동 삭제 | 대화·메시지·근거 확인 기록을 개수로 삭제하지 않음. 모델 요청 크기 제한은 별도로 유지 |
| 중지 후 제공자 취소 응답 지연 | paused 이벤트 직후 재시도가 시작되면 이전 중지가 새 실행을 덮을 수 있음 | 중지 요청 병합, 중지 완료 전 send/retry 거부, 중복 중지 기록 방지 |
| 전송 접수 응답보다 완료 이벤트가 먼저 도착 | 최신 상태와 버튼 활성화가 어긋날 수 있음 | revision 비교 후 즉시 참조 갱신, 중지 작업이 늦은 전송 응답으로 해제되지 않도록 소유권 구분 |
| 대화 목록 조회 중 새 대화/분석 요청 | 늦은 목록이 새 항목·선택·진행 상태를 덮을 수 있음 | revision 기준 목록 병합, 진행 중인 사용자 작업의 선택 유지 |
| 다른 대화 조회 실패 | 화면은 기존 대화인데 수신 대상은 실패한 대화로 변경 | 조회 성공 후에만 선택 변경, 오류 시 기존 수신 유지 |
| 새 대화·재시도·저장 연속 클릭 | React 렌더 전 중복 요청 가능 | 동기 작업 잠금과 폴더 방문별 완료 검증 |
| 결과 저장·클립보드 복사 중 폴더/편집창 이동 | 이전 완료가 새 편집창·미리보기를 닫을 수 있음 | 요청을 시작한 화면과 동일한 편집 대상에만 완료 반영 |
| 주소 검사 진행 중 결과 내보내기 | 단계 검사만 검사하여 미완성 주소 데이터 출력 가능 | 단계·주소 검사 모두 확인, 비활성화 이유와 재시도 안내 |
| Agent가 자기 자신·순환·부재 조건의 순서를 제안 | 저장 후 실행할 수 없는 규칙이 생성될 수 있음 | 제안 정규화와 저장 API 양쪽에서 공통 순서 검증. 최소 0회도 저장 전 거부 |
| 규칙 검토의 범위/순서 표시 | 범위 ID가 생략되고 순서가 내부 clause ID로 표시 | 정확한 범위와 앞선 조건의 패턴 표시 |

## 검증

- 저장소 재시작 후 101개 대화, 502개 메시지, 302개 확인 기록 보존.
- 제공자 취소가 지연되는 동안 중복 중지, 재시도, 새 메시지를 겹치게 한 서비스 테스트.
- 늦은 목록·중복 클릭·A→B→A 복귀 시 작업 소유권 테스트.
- 잘못된 규칙 순서와 저장 revision 불변 테스트.
- 실제 AgentPanel/ResultsView에 합성 지연 응답을 연결한 브라우저 확인: 조회 실패 뒤 기존 응답 수신, 완료보다 늦은 queued 응답, 선택 답변, 새 대화·중지·재시도 연속 클릭, 폴더 왕복, 목록 조회와 분석 요청 겹침, 내보내기 제한, 저장 중 폴더 이동.
- 검증 결과와 CI 링크는 해당 PR에 기록한다.

## 검증 한계

실제 외부 모델이나 OpenCode 프로세스에 실사용 로그를 보내는 검증은 하지 않았다. 도구 선택·질문·복원·오류 경로는 합성 응답과 실제 로컬 저장소로 검증했다. 이전 버전에서 이미 자동 삭제된 데이터는 이번 변경만으로 복구되지 않는다. 매우 긴 대화는 저장되지만 모델 요청 크기 상한을 넘으면 새 대화가 필요할 수 있다.

## CI에서 추가 확인한 사항

- Windows Git 체크아웃이 기존 긴 파일명 테스트 자료에서 실패하여 CI의 체크아웃 전에 `core.longpaths`를 설정했다.
- 배포 의존성 감사에서 발견한 `fast-uri`, `hono`, `qs`를 기존 허용 버전 범위 안에서 갱신했다. `npm audit --omit=dev`는 0건이다.
- 마지막에 추가한 렌더링 테스트의 필수 props를 보완하고 전체 테스트·타입 검사·빌드를 다시 실행했다.
- Windows 체크아웃의 CRLF를 고려하지 않은 기존 장문 로그 테스트를 보완했다. LF·CRLF 양쪽에서 동일한 명령 순서를 검증한다.
