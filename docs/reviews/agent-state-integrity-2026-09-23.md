# Agent 상태·평가 저장 정합성 점검 — 2026-09-23

## 수정 범위

| 재현 조건 | 수정 동작 |
| --- | --- |
| Agent 요약 요청 이후 규칙·수동 판정·파일 구성·평가 이력 변경 | 요청 시점의 프로젝트/평가 revision과 결과 입력 식별값을 초안에 연결한다. 다른 기준이면 재검토를 안내하고 저장을 막는다. 이전 기준 정보가 없는 초안도 그대로 저장하지 않는다. |
| 저장한 요약을 다시 열거나 엔지니어가 이력을 수정한 뒤 이전 초안 재저장 | 저장한 대화/초안 ID를 평가 이력에 영구 보관한다. 다시 열어도 저장 완료를 확인하며 현재 이력의 해석을 표시한다. 충돌 시 이전 payload를 자동 재적용하지 않는다. |
| 평가 결과 확인과 이력 저장 사이에 규칙 변경 발생 | main 프로세스에서 평가 revision을 확인하고, 프로젝트 저장이 끝날 때까지 평가 변경을 대기시킨다. 프로젝트 revision 충돌도 계속 검사한다. |
| 같은 폴더에서 대화 A → B 이동, 앱 재시작 | 미전송 입력을 프로젝트·폴더·대화별로 로컬 보관한다. 전송 접수 시 동일한 입력만 제거하며 저장 실패는 임시 보관으로 알린다. |
| 긴 대화가 모델 요청 한도를 초과 | 전체 원문은 보존한다. 모델 요청은 최근 메시지와 불완전함을 명시한 과거 발췌로 제한하고, 필요한 원문은 대화/메시지/페이지 조회 도구로 찾는다. |
| 다른 폴더에서 대화가 많이 쌓임 | 현재 평가 폴더를 먼저 필터링한 뒤 최근 대화를 선택한다. 오래된 메시지와 긴 메시지의 후반부도 지정 조회한다. |
| CSV/TSV 미리보기 이후 판정·규칙·선택·메타데이터 변경 | 미리보기 생성 당시 입력을 비교해 복사/저장을 막고 새로고침을 제공한다. 단계/주소 검사 또는 메타데이터 저장 중에도 확인을 막는다. |
| React StrictMode에서 초기 효과 재실행 | 화면 생존 여부 참조를 다시 초기화하여 대화 목록이 로딩 상태에 남지 않도록 한다. |

## 검증

- 평가 버전·파일·결과·조건 변경 후 초안 무효화, 저장 ID의 디스크 복원과 사람의 수정 보존.
- 평가 저장 잠금 중 동시 판정 저장 순서, stale revision 거부, 저장 실패 이후 잠금 해제와 IPC 경로.
- 입력 초안의 대화/폴더/프로젝트 분리, 모듈 재시작 복원, 지연 응답, 저장 공간 오류.
- 긴 대화의 내장/OpenCode 요청, 명시적 발췌 표시, 공백/정규식 보존, 과거 대화 페이지 조회.
- 미리보기 입력 변경, 동일 표시값의 다른 파일, 규칙만 변경, 검사/저장 진행 상태, 갱신 후 복구.
- 실제 AgentPanel/ResultsView와 합성 desktop API를 연결한 브라우저 확인: A/B 초안 분리, 새로고침 복원, 전송 접수 후 입력 정리, 저장 뒤 화면 재장착, 이력 직접 수정 보존, 판정 변경 후 이전 요약 저장 차단, 미리보기 무효화와 검사 완료 후 새로고침.
- 1458×862 및 1024×720 데스크톱 창에서 안내와 주요 버튼이 잘리지 않는지 확인.

실제 외부 모델 계정으로 네트워크 호출하거나 Windows/macOS 패키지를 수동 설치하는 검증은 포함하지 않았다. 서비스 테스트의 LLM/OpenCode 응답과 브라우저의 desktop API는 제어 가능한 대역을 사용했다. 최종 전체 테스트·빌드와 운영체제별 CI 결과는 PR에 기록한다.

로컬 최종 검증: 타입 검사 통과, 전체 테스트 737개 통과·3개 건너뜀, Electron 프로덕션 빌드 및 매뉴얼 빌드 통과, 배포용 의존성 취약점 0건. 동일한 문구를 지웠다가 다시 입력한 경우에도 이전 전송 응답이 새 초안을 삭제하지 않는지 revision 기반 회귀 테스트로 확인했다.
