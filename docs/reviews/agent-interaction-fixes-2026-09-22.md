# Agent 기능 및 상호작용 개선 — 2026-09-22

기존 로컬 수정 사항을 유지하면서 Agent의 대화·도구 호출·규칙 조회/수정 경로를 점검하고 수정했다.

## 확인한 문제와 반영 사항

| 확인한 문제 | 수정 |
| --- | --- |
| 내장 실행이 질문 키워드로 도구를 미리 고르고 모델은 답변만 작성 | OpenAI 호환 function tool 호출을 사용해 모델 → 도구 결과 → 다음 호출을 반복. 오류 결과도 모델에 반환하고 호출 수·컨텍스트 크기 제한 유지 |
| 고정된 추천 버튼이 사용자의 다음 행동을 대신 결정 | 고정 추천 버튼과 자동 온보딩 검사 제거. 모델이 작성한 질문/선택지, 자유 입력 답변으로 대화 진행 |
| 질문이 앱 재시작 시 제거됨 | 모델 질문만 지속 저장. 질문 ID로 중복/오래된 답변 차단, 답변과 선택지를 원래 대화에 보존 |
| OpenCode와 내장 실행 사이에서 중간 답변이 누락될 수 있음 | 저장된 대화와 검토 초안을 OpenCode로 다시 전달. 문장을 다시 열 때 삭제하던 필터 제거 |
| 늦은 목록/전송 결과가 최신 질문을 덮음 | 세션 revision 비교, 선택 세션 추적, 폴더 방문별 비동기 완료 보호. 작성 중 문장과 선택 대화를 폴더별로 유지 |
| 중지 직후 도착한 답변이 남음 | 요청 수신 즉시 Abort, OpenCode 세션 생성 시 ID 저장, 종료될 때까지 기다린 후 재시도 가능 상태로 전환 |
| 기본 marker 검사와 사용자 규칙/수동 판정이 분리됨 | evaluation_state_get 추가. 원본 위치·artifact에 묶인 판정과 규칙 버전, 근거 행, 재평가 필요 상태를 조회하고 PASS/FAIL·경향 집계에도 같은 우선순위 반영 |
| 100개 초과 폴더를 Agent가 거부 | 최대 10,000개 허용 범위 유지. 파일 목록과 공개 판정 상세는 페이지 단위로 조회하고 전체 분모는 보존 |
| 특정 파일을 직접 찾고 읽을 연결 정보가 부족 | source_list로 파일명/sourceId 확인 → log_search → 최대 24줄 log_read_window. 선택 범위 밖 조회는 거부 |
| 이력과 현재 판정의 차이를 모델이 알기 어려움 | 이력 조회에 현재 폴더의 저장된 판정과 보고서 수치 차이 제공. 부분 파일 선택은 폴더 전체와 잘못 비교하지 않음 |
| 규칙 변경 대화가 실제 변경으로 이어지지 않음 | 기존 규칙을 기준으로 구조화된 수정안 작성 → 변경 전후 검토 → 규칙 수정 저장. 기준 revision이 바뀌면 덮어쓰기 거부 |
| 후속 질문을 하면 검토 초안이 사라짐 | 새 초안으로 대체되기 전까지 초안과 버튼 유지. 다음 모델 요청에도 검토 조건 전달 |

## 사용 흐름

- “이 평가는 왜 이렇게 됐어?” → 모델이 적용 규칙·수동 판정·근거 행·평가 이력을 도구로 확인한다.
- “이력과 결과가 다른데?” → 현재 판정과 저장 이력의 차이를 확인하고 필요한 질문을 직접 작성할 수 있다. 선택지 또는 자유 입력으로 이어간다.
- “종료가 정확히 두 번이면 PASS로 바꿔 줘” → 기존 규칙을 읽고 수정 전후 조건을 제시한다. `규칙 수정 저장` 후 해당 규칙이 적용된 폴더는 재평가해야 한다.
- “그 조건은 왜 필요해?” → 검토 중 수정안을 유지한 채 같은 대화에서 설명한다.
- 평가 이력의 정리·해석 수정은 일반 대화에서도 요약안으로 제시할 수 있으며 `평가 이력에 저장`으로 반영한다.

읽기 도구는 원본 로그나 프로젝트를 변경하지 않는다. 규칙 수정은 기존 규칙의 조건 수정까지 지원한다. 새 규칙 생성·삭제, 다른 폴더의 원문 접근은 기존 규칙 관리와 폴더 선택을 사용한다. 공용 규칙 수정의 영향과 재평가 필요 상태를 검토 화면에 명시한다.

## 검증

- 전체 테스트: 690개 통과, 3개 기존 건너뜀.
- `npm run build`의 타입 검사와 Electron/renderer 빌드, `npm run docs:build` 통과.
- 새 회귀 테스트: 실제 OpenAI 호환 요청의 tools/messages 형식, 도구 전용 응답, 단계별 도구 결과 전달, 동적 질문과 재시작 후 답변, 잘못된 도구 호출 수정, 중복 전송, 중지 후 늦은 응답, OpenCode 복귀 시 맥락, 반복 호출 상한, 규칙 조회/수동 판정 우선순위, 규칙 해제/초기화, 이력 차이, 100개 초과 파일 목록, 실제 규칙 새 revision 저장과 오래된 제안 거부.
- 브라우저에서 실제 AgentPanel을 합성 API 응답으로 검증: 질문 선택, 폴더 왕복/새로고침 복원, 전송 실패 후 문장 유지, 오래된 queued 응답 뒤 최신 답변 유지, 규칙 변경 전후와 저장 완료 상태.
- 실제 외부 모델의 추론 품질과 실제 OpenCode 프로세스 연결, Windows 설치본 실행은 이번 검증에 포함하지 않았다. API와 실행 흐름은 모의 provider/서비스 및 저장소 테스트로 검증했다.

고정 키워드 라우터의 오래된 테스트는 제거하고 실제 모델 도구 호출 경로를 검증하도록 대체했다. 기존의 다른 로컬 변경 사항은 유지했으며 커밋·푸시는 하지 않았다.
