# 결과 내보내기

`결과`는 현재 필터에 포함된 로그 결과를 편집하고 CSV 파일 또는 TSV 텍스트로 내보내는 목록입니다. `결과 정리`는 N × M 조건표와 집계 추세를 확인하는 별도 화면입니다. 기본 판정과 메타데이터 확인은 [로그 분석 작업](00-log-workbench.md), 반복 작업 절차는 [실무 예제](01-practical-workflows.md)를 참고합니다.

## 내보내기 범위

화면 상단의 `필터 결과 수 / 전체 로그 수`와 하단의 현재 페이지 범위를 확인합니다.

- 검색어는 파일명, 폴더, 상대 경로, Sample·온도·Mode·Grid 값, 결과 코드에 적용됩니다.
- `결과` 필터는 `전체`, `Pass`, `Diag fail`, `Test fail`, `Training fail`, `System halt`, `System reboot`, `Incomplete`, `Unknown`, `Excluded`를 제공합니다.
- `검토` 필터는 `전체`, `검토 필요`, `확정`을 제공합니다.
- 검색어, 결과, 검토 필터는 함께 적용됩니다. `초기화`를 누르면 세 필터가 해제됩니다.
- 표의 열 제목을 누르면 해당 열을 오름차순으로 정렬합니다. 같은 열을 다시 누르면 내림차순으로 바뀝니다. 다른 열을 누르면 그 열의 오름차순부터 시작합니다.
- 표는 한 페이지에 최대 200행을 표시합니다. 페이지를 바꿔도 필터 결과 수와 정렬 순서는 유지됩니다.
- 폴더는 검색창에서 파일명과 조건과 함께 검색할 수 있습니다.
- 선택한 행이 하나라도 있으면 `CSV`와 `TSV`는 현재 필터 안에 남아 있는 선택 행만 현재 정렬 순서로 내보냅니다. 다른 필터에서 숨겨진 선택은 유지되지만 현재 내보내기에는 포함되지 않습니다.
- 선택한 행이 없으면 `CSV`와 `TSV`는 현재 필터 전체를 내보냅니다.
- 현재 내보내기 범위가 0행이면 `TSV 복사`와 `CSV` 버튼이 비활성화됩니다.

행을 클릭하면 원문 로그를 엽니다. `후보`로 표시된 Sample, 온도, Mode, Grid 값을 클릭하면 해당 값을 승인합니다. 네 필드 셀을 눌러 직접 입력하고 `저장`하면 메타데이터 승인 revision이 저장됩니다. 내보내기 전에 각 상태와 원문을 대조합니다. `거절`이면 후보를 다시 검토하고, `미확인`이면 파일명 또는 로그 본문을 수정한 뒤 다시 가져옵니다.

## CSV와 TSV 사용

1. 결과와 검토 필터를 적용합니다.
2. 상단 수가 전달할 행 수와 일치하는지 확인합니다.
3. `CSV` 또는 `TSV 복사`를 누릅니다.
4. `{형식} 내보내기 확인` 창에서 행 수·열 수·첫 5행을 확인합니다.
5. 내보내려면 `확정`, 취소하려면 `취소`를 누릅니다.

`확정` 후 `TSV 복사`는 헤더와 현재 내보내기 범위를 클립보드에 기록하고, `CSV`는 `log-results-YYYY-MM-DD.csv` 형식의 파일로 저장합니다. `취소`를 누르면 내보내지 않습니다. 클립보드 권한 오류가 발생하면 복사 완료 알림이 표시되지 않으므로, 클립보드 권한을 허용한 뒤 같은 절차로 다시 시도합니다.

Excel 붙여넣기에는 TSV 형식이 적합합니다. 탭이 열 구분자이고 각 행은 CRLF로 끝납니다. Excel 통합 문서가 필요하면 TSV 또는 CSV를 Excel에서 연 뒤 통합 문서 형식으로 저장합니다.

## 내보낸 열

첫 행은 아래 헤더이며, 모든 행에서 같은 순서를 사용합니다. 열 이름과 상태 값은 시스템 연계 시 대소문자와 밑줄을 그대로 유지합니다.

| 순서 | 열 | 내용 |
|---:|---|---|
| 1 | `source_id` | 결과표 행의 출처 식별자입니다. 같은 파일명이 있어도 행을 구분하는 기준으로 사용합니다. |
| 2 | `artifact_id` | 로그 내용에 연결된 아티팩트 식별자입니다. 값이 없는 행은 빈 칸입니다. |
| 3 | `source_key` | 출처 루트 식별자와 절대 경로·`..` 경로 성분을 제거한 경로를 조합한 안전한 출처 식별자입니다. |
| 4 | `relative_path` | 로그 경로입니다. 상대 경로이면 백슬래시를 슬래시로 바꾸고, 절대 경로 또는 `..` 경로 성분이 있으면 파일명만 기록합니다. |
| 5 | `run` | 경로 또는 파일명에서 추출한 실행 번호입니다. 없으면 빈 칸입니다. |
| 6 | `filename` | 파일명입니다. 경로 성분은 제거하고 파일명만 기록합니다. |
| 7 | `folder` | 결과표에 표시되는 가져오기 폴더 또는 출처 폴더입니다. 절대 경로 또는 `..` 경로 성분이 있으면 파일명만 기록합니다. |
| 8 | `sample_value` | Sample 값입니다. 값이 없으면 빈 칸입니다. |
| 9 | `sample_state` | Sample 값의 상태입니다. 아래 상태 표를 참고합니다. |
| 10 | `temperature_value` | 온도 값입니다. 화면의 온도에는 `°C`가 표시되며 내보내기 값에는 숫자 문자열만 기록됩니다. |
| 11 | `temperature_state` | 온도 값의 상태입니다. |
| 12 | `mode_value` | Mode 값입니다. 값이 없으면 빈 칸입니다. |
| 13 | `mode_state` | Mode 값의 상태입니다. |
| 14 | `grid_value` | Grid 값입니다. 값이 없으면 빈 칸입니다. |
| 15 | `grid_state` | Grid 값의 상태입니다. |
| 16 | `result` | 결과 코드입니다. `PASS`, `DIAG_FAIL`, `TEST_FAIL`, `TRAINING_FAIL`, `SYSTEM_HALT`, `SYSTEM_REBOOT`, `INCOMPLETE`, `UNKNOWN`, `EXCLUDED` 중 하나입니다. |
| 17 | `result_source` | 결과의 출처입니다. `engineer`, `candidate`, `unreviewed` 중 하나입니다. |
| 18 | `review` | 판정 검토 상태입니다. `confirmed` 또는 `needs_review`입니다. |
| 선택 | `evidence_count`, `selected_evidence_count` | `열 선택`의 `근거` 그룹을 켰을 때 추가됩니다. |

기본 열은 위 표의 1~18번 열입니다. `evidence_count`와 `selected_evidence_count`는 `근거` 그룹을 선택한 경우에만 두 열이 함께 제공됩니다.

### 메타데이터 상태

`sample_value`와 `sample_state`, `temperature_value`와 `temperature_state`, `mode_value`와 `mode_state`, `grid_value`와 `grid_state`는 항상 별도 열로 기록됩니다.

| 상태 | 의미 |
|---|---|
| `candidate` | 파일명에서 정확히 하나의 값을 찾았거나, 파일명에 값이 없을 때 로그 본문에서 정확히 하나의 값을 찾은 상태입니다. 화면에는 `후보`로 표시되며 해당 값을 눌러 승인합니다. |
| `approved` | 메타데이터 승인이 저장된 상태입니다. 승인 값이 있으면 그 값을, 없으면 후보 값을 `*_value`에 기록합니다. 화면에는 `승인`으로 표시됩니다. |
| `rejected` | 메타데이터 후보에 거절이 저장된 상태입니다. 후보 값이 있으면 그 값을 `*_value`에 유지하고 화면에는 `거절`로 표시합니다. 원문 확인 후 값을 사용하려면 값이 하나만 검출되도록 파일명 또는 로그 본문을 수정하고 다시 가져와 새 후보를 승인합니다. |
| `missing` | 올바른 파일명에서 해당 값을 찾지 못했고 로그 본문에서도 찾지 못한 상태입니다. `*_value`는 빈 칸이며 화면에는 `미확인`으로 표시됩니다. 원문에서 값을 확인한 뒤 값이 하나만 검출되도록 파일명 또는 로그 본문을 수정하고 다시 가져옵니다. |
| `malformed` | 파일명이 비어 있거나 `.log` 형식이 아니거나 제어 문자를 포함하거나, 올바른 파일명에 해당 값이 없고 로그 본문에서 같은 항목의 서로 다른 값이 두 개 이상 검출된 상태입니다. `*_value`는 빈 칸이며 화면에는 `미확인`으로 표시됩니다. 잘못된 파일명이나 본문 중복 값을 수정하고 다시 가져옵니다. 파일명 내부 상태가 `conflict`인 경우에도 결과표의 값이 없으면 같은 방식으로 `미확인`으로 표시됩니다. |

## 안전한 텍스트 처리

- CSV와 TSV 모두 UTF-8 BOM으로 시작합니다. CSV 다운로드는 Excel 호환을 위한 BOM을 적용합니다.
- 각 행은 CRLF(`\r\n`)로 구분됩니다.
- CSV 셀은 큰따옴표로 감싸며, 셀 안의 큰따옴표는 두 개의 큰따옴표로 저장됩니다.
- TSV 셀의 탭, CR, LF는 공백으로 바뀝니다. 붙여넣기 시 셀 안의 줄바꿈으로 행이 분리되지 않습니다.
- 셀의 시작 부분에 공백 또는 제어 문자가 있고 그 뒤에 `=`, `+`, `-`, `@`가 오면 앞에 작은따옴표를 붙입니다. Excel이 파일명이나 식별자를 수식으로 실행하지 않도록 하는 처리입니다. 예를 들어 `=cmd.log`는 `'=cmd.log`로 기록됩니다.
- `relative_path`와 `folder`에 절대 경로 또는 `..` 경로 성분이 있으면 파일명만 기록하고, `./` 접두사는 제거합니다.
- `source_key`는 출처 루트 식별자와 정리한 경로를 결합한 식별자입니다. 내보낼 때 경로 부분에서 절대 경로와 `..` 경로 성분을 제거해 절대 경로가 포함되지 않게 합니다. 동일한 파일명이 여러 루트에 있으면 화면의 `폴더명 · ordinal`과 `source_id`, `artifact_id`, `source_key`를 함께 확인합니다.
- 원본 로그 본문, 검색 발췌문, API 키, 절대 경로는 내보내지 않습니다.

## `UNKNOWN`과 검토 필요

`UNKNOWN`은 현재 규칙과 근거로 결과를 결정하지 못한 로그의 결과 코드입니다. 엔지니어 판정이 없고 규칙 결과도 없으며 추론 결과가 `UNKNOWN`이면 `result_source=unreviewed`, `review=needs_review`로 기록합니다. 로그 본문이 비어 있으면 추론 결과가 `UNKNOWN`이 됩니다. 이 행은 원문과 근거를 확인한 뒤 엔지니어 판정을 저장합니다.

`review`는 결과 코드와 독립적으로 기록됩니다. 엔지니어 판정을 저장하면 `result_source=engineer`가 되고, 재검토 요청이 없을 때 `review=confirmed`가 됩니다. 엔지니어 판정에 재검토 요청이 있으면 `review=needs_review`로 기록합니다. 로컬 추론이나 규칙에서 나온 결과는 `result_source=candidate`, `review=needs_review`로 기록하므로 원문과 근거를 확인한 뒤 엔지니어 판정을 저장합니다. `PASS`와 `UNKNOWN` 모두 같은 검토 규칙을 적용합니다.

## 내보내기 검증 체크리스트

- [ ] 검색어, 결과, 검토 필터를 의도한 값으로 설정했습니다.
- [ ] 상단 필터 결과 수와 전달할 행 수를 비교했습니다. 선택 행이 있으면 현재 필터 안의 선택 행 수를 기준으로 확인했습니다.
- [ ] 페이지가 여러 개인 경우에도 내보내기 대상이 필터 결과 전체라는 점을 확인했습니다.
- [ ] 정렬 열과 오름차순·내림차순을 확인했습니다.
- [ ] `candidate`, `approved`, `rejected`, `missing`, `malformed` 메타데이터 상태를 확인했습니다.
- [ ] `UNKNOWN` 행과 `needs_review` 행의 원문, 결과 출처, 근거 수를 확인했습니다.
- [ ] 중복 파일명은 `source_id`, `artifact_id`, `source_key`로 구분했습니다.
- [ ] Excel 붙여넣기에는 `TSV 복사`, 파일 전달에는 `CSV`를 선택했습니다.
- [ ] 수식처럼 보이는 파일명이나 식별자에 작은따옴표가 붙는지 확인했습니다.
- [ ] 기본 내보내기의 헤더가 18개인지 확인했습니다. `근거` 그룹을 켠 경우에만 `evidence_count`, `selected_evidence_count` 두 열이 추가되는지 확인했습니다.
- [ ] 내보낸 데이터에 원본 본문, 검색 발췌문, 절대 경로가 포함되지 않았는지 확인했습니다.
