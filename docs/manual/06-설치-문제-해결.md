# 설치와 문제 해결

## Windows

1. [최신 Release](https://github.com/stpcoder/sequence-control-tower/releases/latest)에서 `Sequence-Control-Tower-Setup.exe`를 받습니다.
2. 설치 관리자를 실행합니다.
3. 기존 설치가 있으면 제거 후 재설치 옵션을 사용할 수 있습니다.
4. 설치 권한이 없는 PC에서는 `Sequence-Control-Tower-Portable.exe`를 사용합니다.

조직 서명이 없는 빌드는 SmartScreen 경고를 표시할 수 있습니다. 회사 보안 정책에 따라 배포 인증서를 적용하십시오.

## macOS

1. 최신 Release에서 `Sequence-Control-Tower-macOS-Universal.dmg`를 받습니다.
2. 앱을 Applications로 이동합니다.
3. Apple Silicon과 Intel Mac에서 같은 Universal 빌드를 사용합니다.

조직 notarization이 없는 빌드는 Gatekeeper 경고를 표시할 수 있습니다. 허용 여부는 회사 정책을 따르십시오.

## 로그가 보이지 않는 경우

- 선택한 폴더와 하위 폴더에 `.log` 파일이 있는지 확인합니다.
- 프로젝트가 맞는지 확인합니다.
- 연결 폴더를 다시 검증합니다.
- 같은 내용의 파일은 hash 기준으로 중복 연결되지 않을 수 있습니다.

## 검색 결과로 이동하지 않는 경우

- `Enter` 또는 `F3`로 다음 결과를 선택합니다.
- 정규식이 켜져 있는지 확인합니다.
- 대소문자와 단어 단위 조건을 확인합니다.
- 전체 검색은 현재 프로젝트에 연결된 로그만 대상으로 합니다.

## 판정 또는 후보 저장 충돌

`최신 revision이 있습니다`가 표시되면 프로젝트를 다시 불러온 뒤 변경을 재적용합니다. 오래 열린 화면에서 저장된 이전 revision이 최신 값을 덮어쓰지 않도록 막는 동작입니다.

## LLM이 느리거나 실패하는 경우

- `Base URL`과 `Model`을 확인합니다.
- `API key` 또는 Vertex 인증 만료를 확인합니다.
- RPM, TPM, `응답 시간 (초)`, `Retries`를 사내 서버 제한에 맞춥니다.
- 대화의 `재시도`를 사용합니다.
- 로컬 검색, 규칙, Pass/Fail 판정과 내보내기는 LLM 없이 계속 사용할 수 있습니다.

## OpenCode가 내부 하네스로 전환되는 경우

- OpenCode 설치 경로와 실행 권한을 확인합니다.
- OpenCode 버전과 앱 버전을 확인합니다.
- Agent 답변의 근거 도구 결과가 남았다면 안전한 내부 전환은 정상 동작한 것입니다.
- 계속 실패하면 앱을 재시작하고 새 대화에서 다시 확인합니다.

## 원본과 복구

원본 `.log` 파일은 수정하지 않습니다. 프로젝트 metadata가 손상되면 앱은 원본 파일을 `.corrupt-*` 또는 `.unsupported-*` 이름으로 보존하고 새 저장소를 만듭니다.
