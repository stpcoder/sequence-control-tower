# LLM 연결 및 검증

LLM 연결은 선택 사항입니다. 로그 폴더 가져오기, 검색, 판정 규칙, 결과표와 패턴 집계는 LLM 없이 이 PC에서 사용할 수 있습니다. 이 문서는 현재 설정 화면에서 할 수 있는 설정 저장과 선택적 연결 확인만 설명합니다.

## 연결 설정

OpenAI 호환 API를 제공하는 로컬 또는 사내 접속 주소를 사용합니다. `Base URL`에는 인증 정보가 없는 HTTP 또는 HTTPS 주소를 입력합니다. 로컬 vLLM의 예시는 다음과 같습니다.

```text
http://127.0.0.1:8000/v1
```

`Model`에는 접속 대상이 제공하는 모델 ID를 입력합니다. 서버가 모델 목록을 제공하지 않아도 모델 ID를 직접 입력할 수 있습니다. `API key`는 접속 대상이 요구할 때만 입력합니다. 사용자 이름, 비밀번호, API key를 `Base URL`에 넣지 마세요.

| 항목 | 입력 내용 | 기본값 및 범위 |
|---|---|---|
| `Base URL` | OpenAI 호환 `/v1` 접속 주소 | 기본값 없음. HTTP 또는 HTTPS만 허용 |
| `Model` | 접속 대상이 제공하는 모델 ID | 기본값 없음. 최대 200자 |
| `API key` | 접속 대상이 요구하는 인증 키 | 선택 사항. 요청에 Bearer 인증으로 사용 |
| `RPM` | 1분 동안 허용할 요청 수 | 기본 8, 범위 1~10,000 |
| `TPM` | 1분 동안 예약할 토큰 수 | 기본 80,000, 범위 1,000~10,000,000 |
| `Timeout` | 요청 1회가 응답을 기다리는 시간 | 기본 60초, 범위 5~300초 |
| `Retries` | 첫 요청 이후 재시도할 최대 횟수 | 기본 2, 범위 0~5 |

`RPM`과 `TPM`은 앱이 관리하는 제한입니다. 공유 접속 주소의 운영 한도보다 높게 입력하지 마세요.

## 설정 저장

1. `설정`에서 `LLM 연결`을 엽니다.
2. 접속 주소, 모델 ID, 필요한 경우 API key와 호출 제한을 입력합니다.
3. `저장`을 누릅니다.

`저장`은 입력한 설정을 이 PC의 앱 데이터에 기록하는 동작이며, 접속 대상에 요청을 보내지 않습니다. 따라서 저장 성공만으로 주소, 인증, 모델 응답이 정상이라고 판단할 수 없습니다.

API key는 운영체제의 암호화 저장을 사용할 수 있으면 암호화해 저장하고, 그렇지 않으면 현재 실행 중인 세션에만 보관합니다. 저장이 끝나면 입력 칸은 비워집니다. Base URL의 host를 바꾸고 새 키를 입력하지 않으면 이전 host의 키는 사용하지 않습니다.

실행 환경에 비공백 `SEQ_LLM_API_KEY`가 있으면 이 값이 앱 저장값보다 우선합니다. 이 상태에서는 설정 화면의 API key 입력 칸이 비활성화되고 `환경변수 관리 중`으로 표시됩니다. 입력한 키는 설정 파일, OS 암호화 저장소 또는 세션에 저장하지 않으며, 다른 설정을 저장할 때 기존 앱 저장 키가 있으면 함께 제거합니다. 환경변수 자체는 앱에서 삭제하지 않습니다.

### API key 입력 칸의 버튼

버튼 라벨과 결과는 입력 칸과 현재 설정 상태에 따라 달라집니다. 입력 칸에 값이 있으면 저장된 키의 상태와 관계없이 `입력 지우기`가 표시됩니다.

| 상태 | 버튼 라벨 | 결과 |
|---|---|---|
| 입력 칸에 저장하지 않은 값이 있음 | `입력 지우기` | 입력 칸만 비우고 `입력 중인 API key를 지웠습니다.`를 표시합니다. 저장된 키는 삭제하지 않습니다. |
| 입력 칸이 비어 있고 현재 `Base URL` host에 저장된 키가 있음 | `저장 키 삭제` | 데스크톱 앱에서 현재 `Base URL` host에 저장된 키를 삭제합니다. 성공하면 `저장된 API key를 삭제했습니다.`를 표시합니다. |
| 입력 칸이 비어 있고 API key가 환경변수로 관리됨 | `환경변수로 관리됨` | 버튼을 사용할 수 없으며, 앱에서 환경변수의 API key를 삭제하지 않습니다. |
| 입력 칸이 비어 있고 저장된 키와 환경변수 키가 모두 없음 | `지우기` | 삭제할 값이 없으므로 아무 동작도 하지 않습니다. |

`저장 키 삭제`는 입력한 설정값을 유지한 채 실행됩니다. 웹 미리보기에서는 저장된 API key를 삭제하지 않고 `웹 미리보기에서는 저장된 API key를 삭제하지 않습니다.`를 표시합니다. `Base URL` host를 바꾸고 새 키 없이 `저장`하면, 저장 키 삭제 버튼을 누르지 않아도 이전 host의 키를 사용하지 않도록 처리합니다.

관리자가 `SEQ_LLM_BASE_URL`, `SEQ_LLM_MODEL`, `SEQ_LLM_API_KEY` 등의 환경 변수로 설정을 관리하는 실행 환경에서는 비어 있지 않은 환경 변수 값이 저장값보다 우선할 수 있습니다. `SEQ_LLM_API_KEY`가 관리 중일 때는 앱에서 API key를 입력하거나 저장할 수 없습니다.

## 모델 목록 확인

`모델 목록 확인`은 선택 기능입니다. Base URL을 입력해야 버튼을 누를 수 있으며, 저장하지 않은 입력값으로도 조회할 수 있습니다. 앱은 입력된 주소에 `/models`를 붙여 인증된 GET 요청을 한 번 보냅니다.

- 접속 대상이 `/models`를 지원해야 합니다.
- 입력 칸에 새 API key가 있으면 그 키를 사용합니다. 비워 두면 같은 host에 저장된 키를 재사용할 수 있지만, 다른 host의 저장된 키는 보내지 않습니다.
- 응답의 모델 ID를 중복 제거해 최대 100개까지 표시합니다. `Model`이 비어 있을 때만 첫 번째 모델을 자동 입력하고, 직접 입력한 값은 덮어쓰지 않습니다.
- 이 조회는 API key를 저장하지 않고, 분석 요청의 호출 제한·재시도 경로도 사용하지 않습니다. 10초 안에 응답하지 않거나 오류가 나면 한 번의 실패로 끝납니다.

목록이 표시되면 `/models` 전송과 응답 형식은 확인된 것입니다. 이것이 `/chat/completions`에 대한 모델 응답이나 실제 분석 성공을 의미하지는 않습니다. `/models`를 제공하지 않는 서버는 모델 ID를 직접 입력해 사용합니다.

`모델 목록 확인`이 실패하면 Base URL의 `/v1` 포함 여부, 접속 대상 실행 상태, VPN 또는 사내망 연결, API key 요구 여부와 권한을 확인하세요.

## Workbench에서 패턴 검토 시작

설정을 저장한 뒤 가져온 로그를 Workbench에서 선택하면, 오른쪽 `판정` pane의 `AI 패턴 검토`에서 선택 로그의 패턴 검토를 시작할 수 있습니다.

1. `검토 관점`에 확인할 내용을 짧게 입력합니다. 비워 두어도 됩니다.
2. 현재 검색어와 최근 검색 관찰이 있으면 함께 반영되도록 `AI 패턴 검토`를 누릅니다. 앱은 코멘트, 현재 검색어, 최근 검색 관찰을 합쳐 길이가 제한된 비어 있지 않은 사용자 코멘트를 분석 요청에 보냅니다.
3. `대기`, 실행 stage, `취소` 상태를 확인합니다. 다른 로그를 선택하거나 Workbench를 떠난 뒤 도착한 이전 작업 업데이트는 현재 화면에 반영하지 않습니다.
4. 완료되면 요약, 추천 태그·검색, 경고, 분석 출처를 확인합니다. 추천 항목은 항목을 직접 눌렀을 때만 현재 로그 검색어로 채워집니다.

이 결과는 원문을 다시 살펴보기 위한 검토용 제안입니다. AI가 `PASS/FAIL` 판정을 확정하거나 판정 규칙을 만들고 적용하지 않습니다. 엔지니어 판정과 규칙 저장은 기존 Workbench 동작에서 별도로 명시적으로 수행합니다.

## 로컬 기능과 LLM 사용 범위

`저장`이나 `모델 목록 확인`만으로 실제 분석 요청 성공을 확인할 수는 없습니다. Workbench의 `AI 패턴 검토`가 실제 분석 요청 경로입니다.

- 로그 가져오기, 원문 검색, 판정 규칙, 근거 줄 선택, 결과표와 패턴 집계는 LLM 연결 없이 로컬에서 수행됩니다.
- 구현상 분석 작업이 다른 경로에서 시작되더라도 LLM 설정이 없으면 결정적 로컬 분석을 사용합니다.
- LLM이 설정되어 있어도 사용자 코멘트가 있거나 부모 파일과 의미 있는 변경이 있을 때만 LLM 요청을 선택합니다. 그 외에는 로컬 분석만 수행합니다.
- LLM 요청이 실패하면 파일 구조와 사용자 코멘트를 이용한 로컬 요약으로 대체합니다. 로컬 기능 자체는 계속 사용할 수 있습니다.

## 선택적 전송 경로 확인

Vertex 같은 다른 OpenAI 호환 접속 주소는 운영 연결 유형을 추가하는 기능이 아니라, 기존 API 전송 형식이 호환되는지 선택적으로 확인할 때만 사용합니다. 일반 운영에서는 승인된 로컬 또는 사내 접속 주소를 사용하세요.

Vertex의 예시 주소 형식은 다음과 같습니다.

```text
https://aiplatform.googleapis.com/v1/projects/${VERTEX_PROJECT}/locations/${VERTEX_LOCATION}/endpoints/openapi
```

`${VERTEX_PROJECT}`와 `${VERTEX_LOCATION}`에는 권한이 있는 값을 넣고, 모델 ID는 직접 입력합니다. 단기 access token은 `API key`에 입력할 수 있지만 문서, 화면 캡처, 저장소에는 남기지 마세요. `/models`를 지원하는 경우에만 `모델 목록 확인`으로 전송 경로를 확인할 수 있습니다. 이 조회는 저장 동작과 분리되어 있으므로 임시 키를 저장하지 않고 확인할 수 있습니다. 지원하지 않으면 이 화면에서 모델 목록을 확인할 수 없습니다.

이 확인은 `/models` 전송과 응답만 점검하며, 운영용 Vertex 연결이나 별도 제공자 기능을 추가하지 않습니다. 이 화면에는 실제 분석 전송을 시작하는 동작이 없습니다. 테스트용 외부 접속을 사용할 때는 회사의 데이터 분류와 LLM 전송 정책을 먼저 확인하고, 확인이 끝나면 입력 칸을 비우고 운영용 주소를 복원하세요. 현재 `Base URL` host에 저장한 키는 `저장 키 삭제`로 삭제할 수 있지만, 환경변수로 관리되는 키는 앱에서 삭제할 수 없습니다.
