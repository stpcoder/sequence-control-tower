# v0.8 평가 이력과 Agent

`평가 이력`은 프로젝트의 평가 조건, 불량 가설, 평가 노드, 연결 로그 근거를 함께 관리하는 화면입니다.

## 평가 이력 시작

1. 왼쪽 메뉴에서 `평가 이력`을 엽니다.
2. `프로젝트 조건`을 펼쳐 제품, SKU, 고객, 대상 장치, 밀도, 정격 전압을 입력합니다. SKU에는 SS/SF/FS/TT/FFS 같은 corner와 16Gb, x8/x16 같은 제품 구성을 기록합니다.
3. `조건 저장`을 눌러 프로젝트에 저장합니다.

조건 입력은 저장 전까지 화면의 임시 초안으로 유지됩니다. 프로젝트를 다시 열거나 저장된 조건이 바뀌면 초안도 최신 조건으로 바뀝니다.

## 평가 추가

1. 오른쪽 `Agent로 정리`에 평가 목적과 확인한 결과를 입력합니다.
2. `Agent에게 정리 요청`을 누릅니다.
3. Agent가 확인한 조건과 근거를 검토하고 필요한 질문에 답합니다.
4. 직접 입력할 때만 `직접 입력`을 펼쳐 가설, 평가, 조건과 로그 근거를 저장합니다.

입력할 수 있는 LPDDR 조건은 SKU, SKEW, Lot, Sample, BL, DQ, Channel, Bank, Bank group, Pattern, MHz, 온도, VDD, Mode입니다. SKU와 시간 SKEW는 서로 다른 값입니다. 부모 평가는 조건을 이어받을 수 있으며, 새 평가의 값이 우선합니다.

평가 목적은 `불량 검출 강화`, `개선 조건 확인`, `동일 불량 재현`, `불량 경향 파악`, `개선 효과 검증`으로 구분합니다. 과거 기록에 목적이 없으면 이름에서 후보만 표시하며 기록을 자동 확정하지 않습니다.

평가 점은 계보에서 선택할 수 있습니다. 선택한 평가에는 실패 로그에서 반복된 온도, VDD, Pattern, DQ를 한 문장으로 해석해 표시합니다. 선택한 평가에 연결된 로그는 `열기`로 다시 로그 화면에서 확인합니다.

로그가 없으면 `로그` 화면에서 폴더를 연결하고 가져온 뒤 평가 이력으로 돌아옵니다. 평가가 없으면 오른쪽에서 불량 가설 또는 첫 평가를 추가합니다.

## 반복된 불량 경향

`반복된 불량 경향`은 저장된 실패 근거에서 SKU, DQ, BL, Pattern, Channel, Bank, 주파수, 온도, VDD, SKEW 값을 집계합니다. 각 행은 특정 조건에서 실패가 모두 발생했는지, 반복적으로 집중되는지, 일부만 확인되는지를 문장으로 보여줍니다.

## 내보내기와 AI 맥락

- `CSV 내보내기`는 프로젝트, 가설, 평가, 근거, 모든 LPDDR 조건, `sourceIds`, 기존 `logRef`를 한 행씩 저장합니다.
- `AI 맥락 복사`는 평가 계보와 반복 불량 경향을 짧은 Markdown으로 클립보드에 복사합니다. Codex, Claude, MCP 클라이언트에 붙여 넣을 수 있습니다. 이 기능은 MCP 서버를 실행하지 않습니다.

## Agent 사용

Agent 패널은 프로젝트 대화를 기본으로 분석합니다. 입력창에서 `/`로 파일을 지정하면 해당 로그를 우선 근거로 사용합니다. 부족한 정보 중 영향이 큰 항목만 질문합니다. 분석 한 번에는 프로젝트 소스를 최대 32개까지 사용합니다.

6,000~7,000줄 로그 원문 전체를 보내지 않습니다. 필요한 검색 결과와 줄 범위만 대상으로 확인합니다. 응답이 느리거나 실패하면 상태를 확인한 뒤 다시 시도할 수 있습니다.

Agent의 진행 중 세션은 앱 프로세스 메모리에만 있습니다. 앱을 종료하면 진행 중 세션은 남지 않습니다. `확인하고 저장`으로 확정한 프로젝트 평가 이력과 근거는 프로젝트에 저장됩니다. 후보는 확인 전까지 프로젝트 이력에 반영되지 않습니다.
