# 평가 이력

## 화면 구성

평가 이력은 연결 폴더 하나를 평가 하나로 표시합니다.

![평가 이력](./images/07-evaluation-history.jpg)

| 영역 | 표시 내용 | 작성 주체 |
|---|---|---|
| 상단 프로젝트 평가 흐름 | 평가 폴더의 관계, 목적, 결과 | 앱 집계와 엔지니어 확인 |
| 가운데 평가 해석 | 선택한 폴더의 실패 조건, 비교 결과, 다음 확인 항목 | Agent 또는 엔지니어 |
| 가운데 조건별 경향 | 선택한 폴더에서 조건별 실패 수와 전체 수 | 앱 자동 계산 |
| 가운데 이 평가의 로그 | 선택한 폴더의 원본 로그 | 앱 자동 연결 |
| 오른쪽 선택 평가 분석 | Agent 분석, 목적, 최종 결과, 이전 평가, 평가 해석 | Agent 제안 후 엔지니어 확인 |

수평선 위의 점 하나가 평가 폴더 하나입니다. 점 색상은 PASS, FAIL, 진행 중, 미정을 표시합니다. 불량 검출·재현, 개선 조건 검증, 불량 경향 확인은 각각 한 줄로 구분됩니다. 아직 분석하지 않은 폴더는 `추가 분석` 줄에 따로 표시됩니다. 각 줄의 선은 `연결할 이전 평가`로 저장한 관계를 따라 이어집니다. 점을 선택하면 가운데 경향과 로그, 오른쪽 입력값이 모두 해당 폴더 기준으로 바뀝니다.

한 줄에 평가가 많아지면 해당 줄만 가로로 이동할 수 있습니다. 줄 이름은 왼쪽에 유지되어 현재 보고 있는 평가 목적을 놓치지 않습니다.

## Agent로 평가 기록 만들기

1. 수평 흐름에서 평가 폴더를 선택합니다.
2. 오른쪽의 `Agent로 분석`을 누릅니다.
3. Agent가 선택 폴더의 로그를 확인할 때까지 기다립니다.
4. Agent가 제안한 결과, 목적, 조건, 해석을 확인합니다.
5. `결과·이력 저장`을 누릅니다.

저장된 내용은 `AI 작성 · 엔지니어 확인`으로 표시됩니다. 저장 전 제안은 `AI 제안`으로 표시됩니다. 파일명과 규칙으로 계산한 값은 `자동 추출`, 사람이 직접 입력한 내용은 `엔지니어 작성`으로 표시됩니다.

## 평가 해석 작성 기준

평가 해석에는 다음 내용을 순서대로 기록합니다.

1. 실패 또는 PASS가 확인된 단계
2. 실패가 집중된 조건
3. 비교 조건에서 달라진 결과
4. 현재 근거로 확정할 수 없는 내용
5. 다음 평가에서 확인할 조건

실패 비율만으로 원인을 확정하지 않습니다. 분모가 작거나 비교 조건이 없으면 추가 확인이 필요하다고 기록합니다.

## 평가 연결

같은 폴더의 RT와 조건 반복은 한 평가에 포함됩니다. 별도 폴더에서 수행한 개선 평가, 검출 강화 평가, 개선 효과 검증은 오른쪽의 `연결할 이전 평가`를 선택해 수평 흐름으로 연결합니다.

평가 목적은 `동일 불량 재현`, `개선 조건 확인`, `개선 효과 검증`, `불량 검출 강화`, `불량 경향 파악` 중에서 선택합니다.
