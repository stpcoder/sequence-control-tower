# Agent 사용

## 하나의 Agent 대화

우측 `Agent` 패널은 하나의 OpenCode 대화로 작동합니다.

- 자유 질문, 조건별 경향, 결과 정리, 평가 이력 제안은 모두 현재 폴더의 같은 OpenCode 세션에서 이어집니다.
- Agent는 프로젝트 이력과 현재 평가 폴더를 조회하고 필요한 읽기 전용 도구를 선택해 호출합니다.
- “이 폴더의 평가를 정리해 줘”처럼 입력하면 같은 대화가 요약안을 만듭니다. `평가 이력에 저장`을 누르기 전에는 프로젝트 기록을 변경하지 않습니다.
- OpenCode가 일시적으로 시작되지 않은 한 요청은 내장 실행 경로로 처리할 수 있습니다. 내장 경로도 모델이 도구를 직접 선택하고 결과를 받은 뒤 다음 도구를 호출합니다. 다음 요청에서 OpenCode로 돌아갈 때 중간 질문과 답변도 함께 전달합니다.
- `평가 이력` 페이지는 Agent가 아닙니다. 확인 후 저장된 평가와 폴더 관계를 보는 프로젝트 기록 화면입니다.

OpenCode Agent는 패키지에 포함된 `lpddr-failure-analysis` Skill과 SCT 분석 도구를 사용합니다. Skill은 평가 단위, 로컬 판정, RT, 개선, Side effect와 확인 저장 기준을 제공합니다. 실행한 도구는 답변 바로 위의 `확인 과정`에서 확인합니다.

## Agent가 사용하는 평가 구조

Agent는 로그를 다음 단위로 구분합니다.

1. `프로젝트`: 같은 제품·고객·개발 목표의 전체 이력
2. `평가 폴더`: 재현, 가속 조건 탐색, 개선 조건 확인, 개선 효과 검증 등 한 가지 평가 목적
3. `Sample·Skew`: 실제 자재와 TT, SS, SF, FS, FF 등 평가 corner
4. `Grid`: 한 번 전원을 인가해 부팅, Training, 테스트 후 종료하는 단위
5. `Sequence`: Grid에서 실행한 명령 순서와 온도, VDD, 주파수, Test Mode 조건

Skew별 Sample 수와 반복 횟수는 따로 계산합니다. 로그 파일 1개를 Grid 1개로 자동 가정하지 않습니다. Agent는 로그의 Grid 또는 전원 인가 경계를 찾은 경우에만 Grid 수를 제시합니다.

불량 분석은 `기준 평가 확인 → 같은 조건 RT → 가속 조건 비교 → 개선 조건 적용 → 새 Fail 위치의 Side effect 확인 → 목표 Sample·Skew 전체 PASS 확인` 순서로 해석합니다. 프로젝트에 처음 저장된 평가가 실제 최초 불량 로그라는 근거가 있을 때만 `최초 불량`으로 해석합니다. 재현 평가부터 기록을 시작했다면 첫 점도 `재현 평가`로 표시합니다.

## 대화 시작

1. 분석할 평가 폴더의 로그를 하나 선택합니다.
2. 화면 오른쪽 아래의 `Agent에게 묻기`를 누릅니다. 모든 페이지에서 위치와 동작이 같습니다.
3. 질문을 입력하고 보내면 대화가 시작됩니다.
4. 별도 대화가 필요할 때만 입력창 아래 `+`를 누릅니다.

자유 대화는 현재 질문과 이전 답변을 기준으로 진행합니다. 고정된 추천 질문이나 분석 단계 선택 버튼은 표시하지 않습니다. 검색 분석·선택 비교·현재 표 분석에서 열면 그 화면의 선택 범위와 분석 맥락을 같은 대화로 전달합니다.

여러 폴더가 연결된 프로젝트에서는 선택한 로그의 폴더만 기본 분석 범위로 사용합니다. 입력창에서 `/`를 입력하면 특정 로그만 지정할 수 있습니다. 선택한 로그는 입력창 위에 한 줄로 표시되며 `×`로 해제할 수 있습니다.

## 검색 행동의 기억과 재사용

1. `Ctrl+F`로 수행한 검색은 먼저 관찰 기록으로 저장됩니다.
2. 검색 후 판정을 저장하면 사용한 검색과 순서를 분석 절차 후보로 기록합니다. 명확한 종료 marker 한 개도 하나의 절차가 될 수 있습니다.
3. `판정 규칙`에서 `다음`을 누른 검색만 확정 분석 절차가 됩니다.
4. 같은 폴더에서는 이 절차를 우선 적용합니다.
5. 다른 폴더에서는 SoC, 부팅 프로파일, Mode, Pattern이 맞을 때만 재사용 후보로 제시합니다. 검색어, 발생 개수, 순서를 현재 폴더에 맞게 수정한 뒤 저장하고 적용합니다.

일반 탐색 검색은 판정 규칙으로 승격되지 않습니다. Agent는 최근 검색과 확정 절차를 구분해 답변합니다.

## Agent가 확인하는 정보

- 파일명 조건: Skew, Sample, Lot, Die, Grid, 온도, VDD, Hot/Room/Cold, HVDD/NVDD/LVDD, 4-Corner, 주파수, Mode
- Grid와 Sequence: 전원 인가 경계, setddrclk/clk.sh, DTVS, erase DDR, reset, Hdiag 실행 순서
- DRAM Fail 위치: CS, Rank, Bank Group, Bank, Row, Column, WR, RD, DQ, BL, Channel, Sub Channel
- SoC와 부팅 단계
- 콘솔 입력 명령과 장비 출력
- 현재 적용된 규칙의 문자열·정규식, 발생 개수와 순서, 적용 범위
- 수동 판정과 최근 일괄평가 결과, 규칙 변경 후 재평가 필요 상태
- PASS, FAIL, halt, reboot marker와 저장된 판정의 차이
- 최근 검색 기록과 엔지니어가 확정한 검색 절차

로그 검색 결과의 `검색 분석`, 결과 화면의 `선택 비교`, 결과 정리의 `현재 표 분석`을 누르면 현재 화면의 선택 범위가 같은 Agent 패널로 전달됩니다. 결과 정리에서는 평가 결과와 Fail 주소 중 선택한 기준, 현재 시각화, 왼쪽·상단 축, 표시 값, 선택한 조건이 함께 전달됩니다. Agent는 화면 숫자를 그대로 복사하지 않고 로컬 분석 도구로 현재 평가 폴더를 다시 계산합니다. Fail 주소 분석에서는 실제 로그 본문의 DQ, BL, Channel, Bank 이벤트를 다시 확인합니다. 분석에 필요한 평가 목적이 미확인인 경우 Agent가 먼저 한 가지를 묻고, 답변이 끝나면 선택한 검색 또는 분석 보기 검토를 이어갑니다.

Agent 답변 아래에 표시되는 파일명을 누르면 근거 로그의 해당 프로젝트 파일을 엽니다. 원문 조회는 현재 대화에서 허용된 로그 범위로 제한됩니다. 다른 폴더는 저장된 평가 요약으로 비교하며 그 폴더의 원문을 읽으려면 해당 폴더로 이동합니다.
- 현재 프로젝트의 폴더별 평가 이력과 과거 프로젝트의 유사 사례

Agent는 현재 폴더의 모든 로그를 로컬 도구 범위에 포함해 조건과 판정을 집계합니다. 앞쪽 일부 파일만 임의로 선택하지 않습니다. 원문은 Agent가 검색 도구로 필요한 구간을 조회하며 원본 로그 전체를 한 번에 LLM으로 보내지 않습니다. 평가 결과의 전체 수와 PASS/FAIL 수는 LLM 응답과 관계없이 폴더 전체 기준으로 계산됩니다.

콘솔 입력은 `UEFI]`, `UEFI>`, `console:/ #`, `root@device #`, `LK>` 같은 prompt 뒤의 명령만 수집합니다. 빈 `UEFI]` prompt, 주석, `META` 헤더, 디버그 출력은 입력 명령에서 제외합니다. 이전 로그에 남은 `console:#`도 호환합니다. `@PASS`, `@FAIL`, halt, watchdog reboot는 장비 출력으로 유지하며, 사용자가 입력한 `UEFI] reset`은 실패 Reboot로 판정하지 않습니다.

응답이 느릴 때는 완료된 확인 항목이 Agent 창의 `확인 과정`에 한 줄씩 표시됩니다. `파일명 조건`, `Grid · Sequence`, `Pass/Fail 판정`, `조건별 경향`, `로그 검색`, `근거 구간`의 요약만 표시하며 원문 로그와 내부 식별자는 진행 화면에 표시하지 않습니다.

최근 Ctrl+F 검색은 엔지니어가 무엇을 확인했는지 파악하는 관찰 기록입니다. Agent는 검색 순서와 일치 개수를 확인하되, 엔지니어가 승인한 절차만 판정 규칙으로 적용합니다. 따라서 단순 탐색과 반복 가능한 판정 절차가 섞이지 않습니다.

## 질문 예시

- `온도와 VDD별 실패 수와 전체 수를 비교해줘.`
- `Skew별 Sample 수와 PASS, FAIL, 미확인을 비교해줘.`
- `Grid마다 적용된 온도, VDD, 주파수, TM과 종료 결과를 정리해줘.`
- `DQ9, Channel 0, Bank Group 1에 실패가 집중되는지 확인해줘.`
- `Hdiag Fail address에서 DQ, BL, Bank, Row, Column 분포를 확인해줘.`
- `실패 단계, 조건 경향, Fail address를 함께 보고 가능한 원인 가설을 좁혀줘.`
- `각 원인 후보의 지지 근거와 반대 근거, 다음에 구분할 평가를 정리해줘.`
- `같은 Sample과 같은 Sequence의 이전 FAIL이 있는지 확인해줘.`
- `이 평가와 유사한 과거 LPDDR5 평가를 찾아줘.`
- `기존 개선 평가에서 효과가 있었던 조건과 새 Side effect가 있었는지 점검해줘.`
- `다음 평가에서 바꿀 조건을 근거와 함께 제안해줘.`

Skew는 TT, SS, SF, FS, FF 같은 평가 corner입니다. PASS와 FAIL 로그에 모두 같은 값으로 들어간 조건은 현재 폴더에서 원인을 구별하지 못하므로 Agent가 원인으로 확정하지 않습니다. 파일명에 있는 DQ, Channel, Bank도 로그 근거 없이 취약 위치로 확정하지 않습니다.

조건별 FAIL률과 Hdiag Fail-address 분포는 분리해서 계산합니다. `Cold 4/5 FAIL`은 평가 조건 경향이고 `DQ0,1,2가 12/18 Fail events`는 실패 위치 분포입니다. Agent는 두 수치의 분모를 섞지 않고 포함된 로그 수도 함께 확인합니다.

불량 원인 질문에서는 실패 단계, 평가 조건 경향, Fail address signature와 같은 이슈의 기존 평가를 함께 비교합니다. 원인 후보마다 지지 근거, 반대 근거, 미확인 항목과 다음 판별 평가를 구분합니다. 과거 유사 사례는 확인 순서를 찾는 데 사용하며 현재 불량의 원인을 자동 확정하지 않습니다.

개선 방법 질문에서는 기존 signature와 FAIL률이 줄었는지, 새로운 DQ, BL, Bank 또는 실패 단계가 나타났는지, 목표 Sample과 Skew 범위에서 반복 PASS가 확인됐는지 점검합니다. 일부 조건의 PASS는 개선 경향으로, 새로운 signature는 Side effect 후보로 남깁니다.

## Agent가 먼저 묻는 경우

새 대화를 열기만 해서는 자동 검사나 고정 설문을 실행하지 않습니다. 질문을 보내면 Agent가 필요한 파일·규칙·판정·이력을 읽습니다. 결론에 영향을 주는 불확실성이 남으면 관찰 근거를 넣어 질문과 선택지를 직접 작성합니다.

선택지를 누르거나 입력창에 자유롭게 답변할 수 있습니다. 답변은 원래 질문, 선택한 파일과 함께 같은 대화에 남습니다. 질문 대기 중 다른 폴더로 갔다 돌아오거나 앱을 다시 시작해도 질문과 선택지가 복원됩니다. 이미 답한 질문에 중복 응답하거나 이전 응답이 늦게 도착해 새 대화를 덮어쓰지 않도록 처리합니다.

예를 들어 “이 평가는 왜 FAIL이야?”라고 물으면 적용 규칙·수동 판정·근거 행을 확인합니다. 현재 판정과 저장된 이력 요약이 다르면 재평가 결과인지, 다른 차수의 기록인지 확인할 수 있습니다. 이 차이는 자동으로 이력을 바꾸는 근거가 아닙니다.

고정된 조건 축에 없는 신규 신호는 버리지 않고 `추가 조건 후보`로 해석에 남깁니다. 다음 평가에서 규칙으로 쓰려면 Agent가 엔지니어에게 한 번 확인합니다.

## 평가 요약 만들기

“이 폴더의 평가를 정리해 줘” 또는 “이력의 해석을 이렇게 수정해 줘”라고 입력하면 현재 대화에서 요약안을 작성합니다. 분석은 백그라운드에서 계속되므로 다른 화면으로 이동할 수 있습니다. Agent 패널을 다시 열면 같은 대화와 진행 상태가 표시됩니다.

LLM 응답이 실패하면 원인을 확인하고 `재시도`를 누릅니다. 이미 실행한 도구의 확인 과정과 사용자 질문은 유지됩니다. 모델이 요약안을 만들지 않은 경우에는 일반 답변만 표시하며 저장 완료로 취급하지 않습니다.

평가 정리는 다음 다섯 부분으로 저장됩니다.

1. `평가 목적`: 이번 폴더에서 확인하려는 불량 재현, 경향, 검출 강화, 개선 또는 검증 목적
2. `평가 결과`: 폴더 전체 로그의 확정 PASS, FAIL, Reboot, Halt, 미확인 수
3. `결과 해석`: 기준 평가 대비 변화, 관찰 사실, 추정과 반대 근거
4. `불량 경향`: Sample, Skew, 온도, VDD, 주파수, Test Mode, Pattern과 Fail address 경향
5. `다음 평가`: 바꿀 변수, 유지할 조건, 대상 Sample, 반복 수와 성공 기준

`평가 결과`는 로컬 판정 데이터로 계산되며 Agent가 숫자를 바꾸지 않습니다. 나머지 네 부분은 Agent가 초안을 작성합니다. `평가 이력에 저장`을 누르면 다섯 부분이 한 버전으로 확정됩니다. 저장 전에는 프로젝트 기록을 변경하지 않습니다.

현재 폴더에 확정 절차가 없으면 testMode, SoC, Boot profile, Pattern이 호환되는 이전 폴더의 확정 검색 절차를 후보로 적용합니다. 온도·VDD·주파수는 비교 변수로 남기고, 현재 폴더에서 엔지니어가 확인하기 전에는 확정 판정으로 저장하지 않습니다.

Agent의 `평가 이력` 도구는 현재 폴더만 보지 않고, 프로젝트에 저장된 다른 폴더의 평가 목적·결과·정성 해석을 같이 읽습니다. 현재 폴더는 별도로 표시되며, 다른 폴더의 원문 로그나 경로는 전달하지 않습니다.

OpenCode Agent는 대화를 시작할 때 내장된 `lpddr-failure-analysis` Skill을 불러옵니다. 이 Skill은 폴더 하나를 평가 하나로 보는 기준, RT·조건 비교·개선·검증·Side effect 관계, 근거 확인 순서를 제공합니다. 평가 이력 연결 시 프로젝트 이력과 현재 폴더의 근거를 읽고 제한된 관계 제안 도구를 사용합니다. `평가 이력에 저장`을 누르기 전에는 이력을 변경하지 않습니다.

평가 흐름은 저장된 이전 평가 연결만 따라갑니다. 저장 순서가 가깝다는 이유만으로 서로 다른 폴더를 한 경로로 합치지 않습니다.

이전 버전에서 만든 폴더 미연결 평가는 진행 경로에서 제외하고 `폴더 연결 필요` 기록으로 구분합니다.

현재 폴더 질문에는 현재 폴더 도구 결과만 사용합니다. 과거 평가 수치나 다른 프로젝트 비교값은 `이전 평가` 또는 `유사 사례` 도구의 근거를 확인하도록 모델에 안내합니다. 저장된 대화는 다시 열 때 문장을 자동 삭제하거나 재작성하지 않습니다.

질문 대기 또는 제안 검토 중 앱을 다시 실행해도 선택한 평가 폴더의 분석 세션을 복원합니다. 종료 시 실행 중이던 분석은 일시 정지 상태로 복원되며 `재시도`로 이어서 실행할 수 있습니다.

## 대화 기록

입력창 아래의 기록 버튼에서 이전 대화를 엽니다. 선택한 폴더의 저장된 대화를 확인할 수 있습니다. 대화에는 질문, 답변, 사용한 도구, 근거 source ID가 저장됩니다. 새 대화와 새 분석은 평가 폴더의 로그를 선택한 뒤 시작합니다.

대화 기록과 검색 기록은 프로젝트에 저장됩니다. 다른 프로젝트에는 자동으로 섞이지 않으며, 같은 프로젝트에서도 선택한 평가 폴더를 기준으로 분석 범위를 제한합니다.


## 중지·실패 후 다시 시도

분석이 실패하거나 중지되면 대화 아래에 원인을 유지하고 `재시도`를 표시합니다. 다른 폴더로 이동한 뒤 이전 요청이 끝나도 현재 폴더의 대화나 저장 상태를 덮어쓰지 않습니다.

Agent는 검색으로 관련 구간을 찾은 뒤 한 번에 최대 24줄을 읽도록 안내받습니다. 필요한 근거를 도구로 추가 조회하며 원문 전체를 한 번에 보내지 않습니다.

## 대화에서 규칙 수정

“종료 문구가 정확히 두 번 나올 때 PASS로 바꿔 줘”처럼 요청할 수 있습니다. Agent는 저장된 규칙을 읽고 `변경 전`과 `변경 후` 조건을 제시합니다. `규칙 수정 저장`을 누르면 새 규칙 버전이 저장됩니다. 대화에서 수정안을 만들기만 해서는 규칙을 바꾸지 않습니다. 수정안에 대해 후속 질문을 해도 검토 중인 조건과 저장 버튼은 유지됩니다.

공유 규칙을 수정하면 그 규칙을 사용하는 폴더 전체에 영향을 줍니다. 저장 후 로그 화면에서 해당 폴더를 재평가해야 결과가 갱신됩니다. 원본 로그와 수동 판정은 유지됩니다. 제안 이후 규칙이 수정·삭제됐으면 저장을 거부하므로 현재 규칙을 다시 읽고 수정안을 요청하세요.

지원 범위는 기존 규칙의 조건 수정입니다. 새 규칙 추가나 규칙 삭제는 로그의 규칙 관리에서 수행합니다. 모델 연결은 OpenAI 호환 도구 호출을 지원해야 하며, 지원하지 않는 연결의 오류를 숨기거나 실행한 것처럼 표시하지 않습니다.

전송 실패 시 작성 중인 문장은 입력창에 남습니다. 폴더를 왕복해도 전송 전 문장은 현재 실행 중인 앱 안에서 보존됩니다. 전송된 질문·답변·선택지는 앱을 다시 시작해도 보존됩니다.

### 대화 보존과 중지

새 대화를 많이 만들거나 한 대화가 길어져도 이전 대화, 메시지, 확인 과정은 개수 제한으로 자동 삭제하지 않습니다. 모델에 보낼 수 있는 요청 크기를 넘으면 원래 대화를 보존한 채 요청을 중단합니다. 필요한 맥락을 정리해 새 대화에서 이어갈 수 있습니다.

중지는 접수 응답이 늦게 오는 동안에도 요청할 수 있습니다. 중지가 끝나기 전에는 재시도가 비활성화되며, 연속 클릭으로 같은 요청을 중복 실행하지 않습니다. 대화 기록을 불러오지 못하면 기존 대화와 수신 중인 답변을 유지하고 오류를 표시합니다.
