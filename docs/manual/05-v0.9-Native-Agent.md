# v0.9 프로젝트 Native Agent

## 샘플 실행

1. 상단 프로젝트 메뉴를 엽니다.
2. `LPDDR6 샘플 열기`를 선택합니다.
3. 오른쪽 아래 `Agent에게 묻기`를 선택합니다.
4. 질문을 입력합니다. 특정 로그만 지정하려면 입력창에서 `/`를 입력하고 파일을 선택합니다.

Agent가 로그 파일명, 콘솔 입력과 종료 marker를 먼저 확인합니다. 샘플에는 7,000줄이 넘는 로그 9개, LPDDR6 Xiaomi 16Gb 프로젝트, VPERI screening, VDD 상향 평가, retention 평가와 LPDDR5 과거 사례가 포함됩니다. macOS에서 만든 샘플 원문은 `~/Library/Application Support/Sequence Control Tower/sequence-intelligence/samples/lpddr6-xiaomi/`에 저장됩니다.

파일명에서 SoC를 확인하지 못하면 프로젝트 로그 전체를 임의로 추정하지 않고 `Qualcomm · UEFI`, `MediaTek · Post-PBL/LK`, `미확인으로 유지` 중 하나를 한 번 묻습니다. 확정한 profile은 질문에 포함된 로그에만 재사용됩니다.

## 기본 질문

- `새 로그 평가 조건 확인`: SoC, Boot profile, SKEW, Die, Sample, Lot, 온도, VDD, 주파수, TM, DQ, BL과 Pass/Fail을 확인합니다.
- `조건별 불량 경향`: 선택 로그의 확정 Pass/Fail 분모와 저장된 평가 근거를 사용하여 SKEW, Die, Sample, 명령, DQ, BL, channel, pattern, 온도, VDD별 실패율을 계산합니다.
- `과거 사례와 다음 평가`: 현재 평가 브랜치와 과거 LPDDR5/LPDDR6 프로젝트를 비교합니다.

직접 질문을 입력해도 됩니다. 프로젝트별 대화와 실행한 도구는 앱을 종료한 뒤에도 유지됩니다.

## Agent가 사용하는 도구

- 프로젝트 조건 조회
- 평가 가설과 브랜치 조회
- 과거 프로젝트 유사 사례 검색
- Ctrl-F와 정규식 검색 기록 조회
- 엔지니어가 확정한 검색 순서와 있음/없음 조건 조회
- 확정 절차의 있음/없음 조건과 실제 로그 발생 순서 일괄 검사
- 파일명 조건 후보 추출
- Qualcomm/MediaTek SoC와 Boot profile별 도달 단계 검사
- Pass/Fail, training fail, reboot, halt, fast fail 검사
- 제한된 로그 검색
- 검색 위치 주변 최대 24줄 읽기
- 조건별 실패 집중도 계산
- UEFI, Bootloader, OS 콘솔의 입력 명령과 장비 출력 분리

Agent는 전체 로그를 LLM에 전송하지 않습니다. 먼저 로컬 검색을 실행하고 필요한 위치만 읽습니다. Pass/Fail과 실패율은 로컬 코드가 계산합니다. LLM은 계산값과 평가 이력을 연결하여 설명합니다.

## 입력 명령 학습

`UEFI> set_freq 9600`, `LK> ...`, `root@device:/ # stressapptest ...`처럼 프롬프트가 분명한 줄은 입력 명령으로 자동 분류합니다. 디버그 출력에 `sleep 20`이라는 문자열이 있어도 입력으로 수집하지 않습니다. `@PASS`, `@FAIL`, training fail, reboot, halt와 fast fail은 명령이 아닌 판정 근거로 유지합니다.

`# sleep 20`처럼 프롬프트가 짧아 입력인지 출력인지 불확실하면 Agent가 한 번 묻습니다. `입력 명령 · 형식 기억` 또는 `장비 출력 · 형식 제외`를 선택하면 해당 프롬프트 형식을 프로젝트에 저장하고 다음 로그부터 재사용합니다. `이번 줄만 입력`은 현재 줄에만 적용합니다. 질문은 모호한 새 형식이 있을 때만 표시됩니다.

## OpenCode와 내장 Agent

입력창 아래의 작은 상태점으로 현재 backend를 확인합니다.

- 초록색: 로컬 OpenCode headless harness가 Sequence Control Tower MCP 도구를 호출합니다.
- 회색: OpenCode가 없거나 호환되지 않아 내장 분석이 같은 읽기 전용 도구를 실행합니다.

OpenCode에는 shell, 파일 편집, 전체 파일 읽기, 웹 검색 권한이 없습니다. 프로젝트 데이터 수정은 앱에서 엔지니어가 확정한 경우에만 수행합니다.

## 느린 사내 LLM

메시지를 보내면 먼저 대화가 저장되고 `대기 중` 또는 `도구 실행 및 분석 중` 상태가 표시됩니다. 다른 화면으로 이동해도 작업과 대화가 유지됩니다.

- 응답이 늦으면 `중지`를 선택할 수 있습니다.
- timeout 또는 사용량 제한이 발생하면 로컬 도구 결과가 대화에 남습니다.
- `재시도`를 선택하면 같은 요청을 다시 실행합니다.
- 앱이 분석 중 종료되면 다음 실행에서 해당 대화가 `paused` 상태로 복구됩니다.

## 평가 문맥 저장

`평가 이력` 화면에서 불량 가설과 평가를 추가하고 이전 평가와 분석 흐름을 지정합니다. 각 평가에 로그 근거와 SoC, SKEW, Die, Sample, Lot, DQ, BL, channel, bank, bank group, pattern, 주파수, 온도, VDD, TM을 저장합니다. Die가 파일명이나 로그에 없으면 미확인 상태로 둡니다.

프로젝트 Agent는 이 평가 이력을 다음 대화에서 자동으로 조회합니다. 저장된 근거가 없는 인과관계는 `추정` 또는 `미확인`으로 표시합니다.

## Ctrl-F 기록

로그 워크벤치의 현재 로그, 열린 로그, 프로젝트 전체 검색 결과는 프로젝트 검색 기록에 저장됩니다. Agent는 검색어, 문자열/정규식 구분, 검색 범위와 일치 개수를 조회할 수 있습니다. 로그 원문 전체와 절대경로는 검색 기록에 저장하지 않습니다.

## 분석 절차 기억

1. 로그에서 평소처럼 Ctrl-F 또는 정규식 검색을 순서대로 실행합니다.
2. 우측 `판정`에서 결과를 확정합니다.
3. 의미 있는 검색이 두 개 이상이면 `이번 분석`이 한 번 표시됩니다.
4. 평가 목적을 선택하거나 직접 입력하고 `저장`을 누릅니다.

검색 순서, 현재 로그의 일치 개수와 0건 확인이 프로젝트 분석 절차로 저장됩니다. Qualcomm은 PBL/XBL/ABL/UEFI 계열, MediaTek은 Post-PBL/LK 계열 Boot profile로 구분합니다. Training, OS, Memory test, Halt와 Reboot도 각각 확인합니다. 같은 절차는 다음 평가에서 자동으로 인식하여 다시 묻지 않습니다.

RT는 부팅 단계로 저장하지 않습니다. 같은 Sample과 같은 Sequence signature로 이전 FAIL을 다시 수행했을 때 이전 평가와 RT 관계로 연결합니다. 파일명에 RT가 있지만 이전 평가를 찾지 못하면 자동 연결하지 않고 미연결 RT로 표시합니다.

처음 확인된 명령은 Agent 대화에서 목적을 한 번만 묻습니다. 선택하거나 직접 입력한 답은 현재 프로젝트와 SoC 범위의 명령 지식으로 저장되어 다음 로그 분석에 재사용됩니다.

Ctrl-F 기록만으로 판정 규칙을 만들지 않습니다. 엔지니어가 평가 목적을 확인한 절차만 Agent가 다음 파일명 해석과 프로젝트 질문에 사용합니다. 프로젝트 대화의 질문과 답변도 저장되어 새 대화에서 이전 분석 맥락으로 조회됩니다.
