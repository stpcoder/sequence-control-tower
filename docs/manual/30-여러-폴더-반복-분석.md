# 여러 폴더 반복 분석

이 문서는 `로그` 화면에서 여러 폴더의 `.log` 파일을 등록하고, `Run1`과 `Run2`를 같은 판정 규칙으로 확인하는 절차를 정의합니다. `Run1`과 `Run2`는 작업자가 정한 폴더명입니다. 앱에 별도의 `Run1`·`Run2` 실행 번호 필드는 없습니다.

## 사용할 입력

다음 구조를 준비합니다. 각 폴더에는 하위 폴더를 포함해 `.log` 파일만 분석 대상에 넣습니다.

Windows:

```text
C:\Logs\Run1\logs\SMP-A17.log
C:\Logs\Run2\logs\SMP-A17.log
```

macOS:

```text
/Users/<user>/Logs/Run1/logs/SMP-A17.log
/Users/<user>/Logs/Run2/logs/SMP-A17.log
```

macOS 경로의 `<user>`는 현재 macOS 계정의 짧은 사용자 이름입니다. 실제 계정 이름으로 바꿔 입력합니다.

`Run1/logs/SMP-A17.log`의 최소 입력:

```text
stressapp: start
hidag: start
@PASS DIAG_COMPLETE
normal_end: true
```

`Run2/logs/SMP-A17.log`의 최소 입력:

```text
stressapp: start
hidag: start
DIAG_FAIL lane=2 code=DG_021
@FAIL code=DG_021
```

확인 항목: 두 파일의 확장자가 실제로 `.log`이고, 위 로그 문구가 줄 단위로 저장되어 있는지 확인합니다. 파일명이 같아도 부모 폴더의 실제 경로가 다르면 별도 출처로 유지됩니다.

## Windows에서 여러 폴더 선택

1. 앱을 열고 `로그` 화면으로 이동합니다.
2. 왼쪽 목록에서 `로그 폴더 열기`를 누릅니다. 메뉴 단축키를 사용할 때는 `Ctrl+O`를 누릅니다.
3. 폴더 선택창에서 `C:\Logs\Run1\logs`를 한 번 클릭합니다.
4. `Ctrl`을 누른 채 `C:\Logs\Run2\logs`를 클릭합니다. 두 폴더가 선택 상태인지 확인합니다.
5. `폴더 선택` 또는 `Select Folder`를 눌러 확정합니다.

기대 결과:

- 가져오기 완료 알림에 등록한 로그 수가 표시됩니다.
- 왼쪽 목록에 `logs · 1`과 `logs · 2`가 각각 표시됩니다. 같은 폴더명은 내부의 서로 다른 폴더 식별자로 분리하고, 화면 라벨에 순번을 붙입니다.
- 각 그룹을 펼치면 `SMP-A17.log`가 한 개씩 표시됩니다.
- 파일 내용은 폴더 선택 시 전부 열리지 않습니다. 파일을 선택할 때 필요한 원문 구간을 읽습니다.

확인 항목: `logs · 1`의 파일을 선택했을 때 상대 경로가 `SMP-A17.log`로 표시되고, `logs · 2`의 파일을 선택했을 때도 같은 상대 경로가 표시되는지 확인합니다. 두 행을 합치지 않습니다.

## macOS에서 여러 폴더 선택

1. 앱을 열고 `로그` 화면에서 `로그 폴더 열기`를 누릅니다. 메뉴 단축키를 사용할 때는 `⌘O`를 누릅니다.
2. 폴더 선택창에서 `/Users/<user>/Logs/Run1/logs`를 한 번 클릭합니다.
3. `Command(⌘)`을 누른 채 `/Users/<user>/Logs/Run2/logs`를 클릭합니다. 두 폴더가 선택 상태인지 확인합니다.
4. `Choose` 또는 `선택`을 눌러 확정합니다.

기대 결과와 확인 항목은 Windows 절차와 같습니다. 화면에는 절대 경로가 아니라 선택 폴더 라벨과 선택 폴더 기준의 상대 경로만 표시됩니다. 여러 선택이 표시되지 않는 파일 선택 환경에서는 한 폴더를 확정한 뒤 `로그 폴더 열기`를 다시 눌러 나머지 폴더를 추가합니다.

## 가져오기 제한과 제외 항목

현재 `로그 폴더 열기`는 `.log` 확장자만 허용하고 하위 폴더를 재귀적으로 검사합니다.

| 항목 | 실제 동작 | 확인할 알림 또는 결과 |
|---|---|---|
| 한 번에 선택하는 폴더 | 최대 100개 | 100개 초과 시 가져오기 오류 |
| 한 번의 폴더 가져오기에서 수집하는 파일 | 최대 10,000개 | `10,000개 제한 도달` |
| `.log`가 아닌 일반 파일 | 등록하지 않음 | `제외` 수에 포함 |
| 하위 심볼릭 링크 폴더·파일 | 따라가지 않음 | `제외` 수에 포함 |
| 선택 항목 자체가 심볼릭 링크 폴더 | 폴더 전체 거부 | `심볼릭 링크 폴더는 가져올 수 없습니다.` |
| 같은 파일 내용 | SHA 기준으로 원문 저장 공간을 공유 | 출처 행과 상대 경로는 각각 유지 |
| 같은 경로의 내용 변경 후 재가져오기 | 새 SHA의 파일로 등록 | 이전 판정은 새 내용에 자동 적용하지 않음 |

제한에 도달하면 그 시점까지 수집한 파일만 등록합니다. 누락된 파일을 자동으로 이어서 수집하지 않습니다. 더 수집하려면 다른 하위 폴더를 별도로 선택해 가져옵니다.

확인 항목: 완료 알림의 `등록`, `실패`, `제외` 수와 `10,000개 제한 도달` 문구를 기록합니다. `실패` 또는 `제외`가 1개 이상이면 규칙 적용 전에 누락 파일의 경로와 확장자를 원본 폴더에서 확인합니다.

## Run1: 검색 기록과 규칙 생성

1. `logs · 1`을 펼치고 `SMP-A17.log`를 선택합니다.
2. `Ctrl+F`(Windows) 또는 `⌘F`(macOS)를 누릅니다.
3. 검색어에 `@PASS`를 입력합니다. 검색 방식은 literal, 대소문자 구분은 끕니다.
4. 검색 결과가 `1`건으로 표시되고 `@PASS DIAG_COMPLETE` 줄로 이동하는지 확인합니다.
5. 검색어를 `normal_end`로 바꿉니다. 결과가 `1`건인지 확인합니다.
6. 검색어를 `@FAIL`로 바꿉니다. 결과가 `0`건인지 확인합니다.
7. `@PASS` 검색과 `normal_end` 검색 결과에서 근거로 사용할 줄 왼쪽 원형 버튼을 눌러 `원문 북마크`로 지정합니다.
8. 오른쪽 `결과`에서 `Pass`를 선택합니다. 기존 판정이 있으면 표시되는 `기존 ... → ... 변경 확정`을 눌러야 새 revision이 저장됩니다.

현재 파일만 검색하려면 `Ctrl+F`(Windows) 또는 `⌘F`(macOS)를 사용합니다. 등록된 모든 파일을 검색하려면 `Ctrl+Shift+F` 또는 `⌘⇧F`를 사용합니다. 규칙에 사용할 검색 기록은 로그별로 저장되므로, Run1과 Run2의 규칙을 만들 때는 각 파일을 선택한 상태에서 검색합니다.

각 검색이 완료되면 해당 로그의 검색 기록에 검색어, literal/regex 방식, 대소문자 설정, 일치 여부, 일치 수가 기록됩니다. 검색을 다시 입력하는 것만으로는 판정 근거가 되지 않습니다.

확인 항목:

- `@PASS` 관찰: 일치 `1`회, 해당 로그의 검색 기록에 저장됨
- `normal_end` 관찰: 일치 `1`회, 해당 로그의 검색 기록에 저장됨
- `@FAIL` 관찰: 일치 `0`회, 해당 로그의 검색 기록에 저장됨
- 원문 북마크: `@PASS`와 `normal_end` 줄 번호가 표시됨
- 엔지니어 판정: `PASS`가 저장됨

### Run1 판정 규칙 저장

1. 오른쪽 `분석 규칙`에서 `판정에 사용할 검색을 선택하세요` 아래의 `@PASS`와 `normal_end`를 선택합니다.
2. 두 검색이 모두 선택된 상태에서 `표시된 순서대로 나타나야 함`을 켭니다. 현재 파일에서 두 검색이 모두 일치해야 이 항목이 표시됩니다.
3. 규칙 설명에 `그러면 PASS`가 표시되는지 확인합니다.
4. `규칙 저장`을 누릅니다.
5. 완료 알림에서 `분석 규칙을 저장했습니다.`를 확인합니다.

기대 결과: `PASS` 규칙이 현재 분석 프로젝트에 revision으로 저장됩니다. 새 규칙은 후보 규칙이며, 저장 즉시 사람의 모든 판정을 확정하지 않습니다. `Unknown` 판정은 규칙으로 저장할 수 없습니다.

## Run2: 같은 규칙의 재실행과 검토

1. `logs · 2`의 `SMP-A17.log`를 선택합니다.
2. `@PASS`, `normal_end`, `@FAIL`을 각각 검색하고 각 결과 수를 확인합니다.
3. `@PASS`와 `normal_end`는 `0`건, `@FAIL`은 `1`건인지 확인합니다.
4. `DIAG_FAIL`을 검색하고 `1`건인지 확인합니다.
5. `@FAIL code=DG_021`와 `DIAG_FAIL lane=2 code=DG_021` 줄을 원문 북마크로 지정합니다.
6. 오른쪽 `결과`에서 `Diag fail`을 선택하고 저장합니다.
7. Run1에서 저장한 `PASS` 규칙이 Run2의 `DIAG_FAIL` 파일을 PASS로 바꾸지 않는지 확인합니다. 규칙의 모든 절이 맞지 않으면 일치하는 규칙이 없는 예외가 됩니다.
8. Run2의 근거를 선택한 뒤 `분석 규칙`에서 Run2용 `DIAG_FAIL` 규칙을 저장할 수 있습니다. `규칙 저장`을 누르기 전 결과가 `Diag fail`인지 확인합니다.
9. 여러 규칙을 확인하려면 `전체에 미리 적용`을 누릅니다.

기대 결과:

- Run1 파일: `Pass` 또는 엔지니어가 저장한 `PASS` 유지
- Run2 파일: 엔지니어가 저장한 `DIAG_FAIL` 유지
- 기존 엔지니어 판정과 규칙 결과가 다르면 엔지니어 판정을 유지하고 `검토 필요` 예외로 표시
- 일괄 적용 완료 후 `조건 일치` 수와 `예외 N개 확인`이 표시됨

확인 항목: `예외 N개 확인`을 누르고 파일별 `검토 이유`를 확인합니다. `예외 N개 확인`에서 `N`은 예외 개수입니다. `Ln N 근거로 이동`에서 `Ln N`은 원문 줄 번호입니다. `Ln N 근거로 이동`을 누르면 해당 원문 줄이 열립니다. `일치하는 규칙 없음`, `동순위 규칙 충돌`, `판정 근거 누락`, `로그 검사 실패`를 각각 원문과 규칙 조건에 대조합니다. 확인하지 못한 결과는 `Unknown`으로 유지합니다.

## 재시작·재실행·다시 열기

1. Run1 규칙 저장과 Run2 검토가 완료된 뒤 앱을 정상 종료합니다.
2. 같은 앱을 다시 엽니다.
3. `로그` 화면에서 `logs · 1`, `logs · 2` 그룹과 파일 수를 확인합니다.
4. Run1 파일을 열고 `@PASS`를 검색합니다. Run2 파일을 열고 `DIAG_FAIL`을 검색합니다.
5. Run1 파일의 오른쪽 판정이 `PASS`, Run2 파일의 오른쪽 판정이 `DIAG_FAIL`인지 확인합니다.
6. Run1 파일에서 `분석 규칙 저장` 또는 기존 규칙 목록을 열어 저장된 규칙이 보이는지 확인합니다. 규칙 창이 닫혀 있으면 `분석 규칙 저장`을 눌러 다시 엽니다.
7. Run1·Run2 파일의 검색 기록, 영속 판정, 저장된 규칙 revision, 일괄 판정 결과가 복원되는지 확인합니다.
8. 원문 북마크는 복원되지 않습니다. Run1의 `@PASS`와 `normal_end` 줄, Run2의 `@FAIL code=DG_021`와 `DIAG_FAIL lane=2 code=DG_021` 줄을 각각 다시 원문 북마크로 선택합니다.
9. Run2 폴더의 내용이 변경되었으면 `로그 폴더 열기`로 Run2 폴더를 다시 가져옵니다. 새 SHA가 생성된 파일에는 이전 판정을 자동 적용하지 않고 다시 검토합니다.

기대 결과: 가져온 로그와 로그별 검색 기록, 영속적으로 저장된 판정, 규칙 revision, 일괄 판정 결과가 다시 표시됩니다. 파일별 원문 북마크와 선택한 근거 줄은 재시작 후 복원되지 않으므로 각 파일에서 다시 선택해야 합니다. 파일을 다시 가져오면 같은 폴더 출처와 상대 경로에서 최신 SHA의 파일만 목록에 남습니다. 다른 폴더 출처의 동일 파일은 별도 출처로 남습니다.

확인 항목: 재실행 후 그룹 수, 파일 수, 검색 기록, 판정, 규칙 revision, 일괄 판정 결과를 Run1·Run2별로 기록하고, 원문 북마크를 다시 선택했는지도 확인합니다. 어느 하나라도 달라지면 동일한 파일인지, 폴더가 이동하지 않았는지, 파일 내용의 SHA가 바뀌지 않았는지 먼저 확인하고 규칙을 재저장합니다.

## 결과표 확인

1. `결과표`로 이동합니다.
2. 검색 상자에 `SMP-A17`을 입력합니다.
3. `검토` 필터를 `검토 필요`로 바꿉니다.
4. Run1과 Run2의 `폴더`, `결과`, `판정 검토`, `근거` 열을 확인합니다.
5. 파일명에서 추출된 `Sample`, 온도, `Mode`가 원문과 일치할 때만 후보 값을 눌러 승인합니다.

기대 결과: 결과표의 각 행은 파일명, 폴더 라벨, 결과, 검토 상태, 근거 수를 별도로 표시합니다. 폴더명이 같아도 `logs · 1`과 `logs · 2`의 출처를 합치지 않습니다. `검토 필요` 행은 CSV/TSV를 내보내기 전에 원문과 규칙을 다시 확인합니다.
