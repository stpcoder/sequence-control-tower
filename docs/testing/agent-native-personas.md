# Agent Native 상호작용 QA

평가 폴더 하나를 평가 하나로 취급한다. 같은 평가에서는 화면을 이동해도 대화를 이어가고, 다른 폴더의 검색 절차는 후보로만 제시한다.

## 재현 평가 담당

1. 로그에서 `UEFI`, `@FAIL`, `@PASS`를 순서대로 검색한다.
2. 결과에서 같은 Sample·SKEW·Sequence의 RT 로그를 선택한다.
3. Agent에게 재현 여부를 묻는다.

확인 항목: 로그 검색과 결과 질문이 같은 폴더 대화에 남아야 한다. 검색 기록은 엔지니어가 확정하기 전까지 판정 규칙이 아니다.

## 가속 조건 담당

1. 결과 정리에서 주파수를 왼쪽 축, 온도·VDD를 상단 축으로 선택한다.
2. 불량률 또는 FAIL 판정 수로 조건을 비교한다.
3. Agent 분석 후 추천 보기를 적용한다.

확인 항목: Agent는 PASS/FAIL 분모를 다시 계산한다. 추천 보기는 저장 전에 화면에만 적용되며 되돌릴 수 있다.

## TM 개선·Side effect 담당

1. 개선 전·후 평가 폴더를 구분한다.
2. Fail 주소 기준에서 DQ × BL Heatmap을 확인한다.
3. Agent에게 기존 signature 감소와 새로운 DQ·BL 발생을 함께 묻는다.

확인 항목: 파일명 후보가 아닌 실제 Fail address event 수를 사용한다. 새로운 위치의 FAIL은 개선 완료가 아니라 Side effect 후보로 설명한다.

## 프로젝트 담당

1. 재현·가속·개선 평가 결과를 여러 폴더에서 선택한다.
2. Agent에게 평가 관계와 다음 평가를 묻는다.

확인 항목: 여러 폴더 선택은 프로젝트 비교 대화로 분리한다. 다른 폴더의 원본 로그를 한 평가로 합치지 않는다.

## QC 부팅·Training 담당

1. SM 계열 평가 폴더를 선택한다.
2. Training FAIL이 UEFI 도달 전인지 묻는다.
3. 같은 대화에서 결과 판정 근거를 다시 확인한다.

확인 항목: QC 부팅 프로파일과 PASS/FAIL 도구를 함께 사용한다. UEFI가 모든 장비의 공통 단계라고 표현하지 않는다.

## MTK 부팅·Reboot 담당

1. MTK 평가 폴더를 선택한다.
2. LK, LK2, OS 순서와 console 입력을 확인한다.
3. TEST_FAIL, SYSTEM_HALT, SYSTEM_REBOOT를 구분하도록 요청한다.

확인 항목: QC 폴더 로그가 섞이지 않아야 한다. MTK 부팅 단계, 입력 명령, 종료 marker를 각각 근거로 사용한다.

## 4-Corner 담당

1. 같은 Sample의 HH, CH, HL, CL Grid를 선택한다.
2. 온도와 VDD별 불량률을 요청한다.
3. Agent 추천 Heatmap을 미리 적용하고 되돌린다.

확인 항목: 파일 수가 아니라 판정된 Grid 또는 로그의 분모를 표시한다. 추천 보기는 명시적으로 저장하기 전까지 임시 상태다.

## 장문 Halt 판정 담당

1. `stressapp start`, `@PASS`, `@FAIL`, watchdog 또는 reboot marker를 검색한다.
2. PASS/FAIL marker가 없는 중단 로그를 Agent에게 확인한다.

확인 항목: 전체 로그를 LLM에 전달하지 않는다. 검색과 근거 구간만 읽고, 증거가 부족하면 SYSTEM_HALT 또는 SYSTEM_REBOOT를 임의 확정하지 않는다.

## 분석 절차 재사용 담당

1. 평가 A에서 Ctrl-F 순서를 판정 규칙으로 확정한다.
2. 평가 B에서 해당 절차의 호환 적용을 요청한다.
3. 맞지 않는 검색 조건은 평가 B에서 수정한다.

확인 항목: 평가 A의 절차는 평가 B에서 후보로만 적용된다. 수정된 절차는 평가 B 범위에 따로 저장된다.
